## 2026-11-16 游戏详情第二轮（当前实现）

本轮沿用樱纸档案的视觉系统，只重构详情页内部的信息组织。证据保存在 `outputs/redesign-detail/2026-11-16/refactor-round2/`、`refactor-round3/` 与 `refactor-round4/`，改动前检查点在 `outputs/redesign-detail/2026-11-16/checkpoints/2026-11-16-before-screenshot-refactor/`。

- **概览**：改为单列“作品档案”。简介、别名、标签、游戏资料、来源与库编号全部收进“关于这部作品”同一张卡片；独立的“游戏资料”卡片删除，用户评价卡放在档案下方。
- **简介排版**：简介保持单栏并占满档案卡宽度，不再使用多栏文字或 68ch 限宽。宽屏下以完整的横向文本区消除卡片右侧空白。
- **用户评价**：原“用户备注”统一改称“用户评价”，当前来源标记为“本地”。评价卡保留单一来源条目结构，后续可在同一区域增加 Bangumi、Kungal 等社区来源，不把本地手写内容伪装成外部评分或评论。
- **游玩记录**：移除五列表格，改为会话日志。每条记录先给出日期与星期，再显示起止时间、时长、结束状态和可选备注；修正与自动记录状态保留，编辑和删除仍是独立图标操作。
- **启动配置**：路径改成“游戏目录 + 可执行文件名”的组合字段，标签压在输入框上边框；启动参数和兼容包装器各占一整行卡片。兼容包装器卡分别列出 Locale Emulator 与 Magpie，并各自保存启用状态。显示偏好卡已移除，显示器与全屏沿用已保存配置，不在详情页重复设置。
- **即时保存**：启动配置不再提供底部“保存配置 / 保存并启动”按钮。文本改动经 350ms 防抖自动保存，目录、可执行文件和包装器开关在选择后立即保存；界面不显示常驻自动保存提示，仅在失败时显示错误。
- **兼容包装器**：详情页为 Locale Emulator 与 Magpie 分别提供启用开关，不再填写程序或参数。设置页分别维护两者的路径与参数；Locale Emulator 作为命令包装器把游戏 exe 交给 `LEProc`。启用 Magpie 时，管理器等待游戏窗口出现，按实际 exe 路径与窗口类名写入 `autoScale` 规则，再以 `-t` 托盘模式启动或重载 Magpie，因此不依赖用户手动按快捷键。两类包装器可同时启用，启动顺序为先 Locale Emulator、后 Magpie。旧版单包装器设置与启动配置在读取时迁移为 Locale Emulator。
- **来源编号**：新增 `work_source_links` 持久化表。多源匹配应用时保存本轮全部匹配来源的编号；单源搜索导入后补跑一次来源匹配，并把可确认的编号写入同一组记录，已有编号不会被补跑覆盖。来源入口不再依赖是否导入过该来源的某个字段。
- **外部页面**：主操作右侧在存在来源编号时显示带文字的 Bangumi 与 Kungal 按钮，分别打开 `bgm.tv/subject/...` 和 `kungal.com/galgame/...`。图标使用两站自己的 favicon 静态资源；没有有效来源 ID 时不显示对应按钮。
- **页签高度**：切换详情页签时不再为了保留旧滚动位置而人为撑高内容面板；滚动位置直接夹到新内容的末尾，避免下方出现大块空白。
- **封面编辑**：内联编辑器的“封面与资料”标题下不再放说明文字；“更换封面 / 本地图片”使用同一按钮样式、等宽两列，并与封面左右边缘对齐。
- **响应式**：概览在 960px 以下改为单列，顺序为简介、评价、游戏资料；路径组合在 960px 以下折为上下两行，参数区在 1100px 以下折为单列；390px 下会话日志改为日期、内容、操作三段式布局。

## 2026-11-17 C9 数据安全与恢复界面（当前实现）

“设置 → 数据与关于”沿用现有纸面设置行，不新增独立管理页。数据库行显示文件大小与完整性；备份与恢复行提供“立即备份 / 恢复”，最近备份时间与大小直接写在行内；迁移行显示已应用迁移和待执行数量，并打开本地备份目录；诊断日志使用同一套图标按钮打开本地 JSONL 目录。恢复通过统一确认框说明“先保留当前数据库、重启后完成替换”，避免把文件复制伪装成立即完成。

- 备份选择使用系统保存对话框，只接受 `.sqlite3`/`.db`；恢复选择使用系统打开对话框，随后由后端检查 SQLite 文件头、`quick_check` 和必需数据表。
- 崩溃回退页不属于正常页面导航：它只在大面积渲染异常时覆盖窗口，显示“重新载入”和“打开诊断日志”，并明确本地数据库与游戏文件没有被删除。
- 浏览器预览继续显示同一设置结构，但备份、恢复和打开日志按钮禁用；不伪造本地文件操作。

## 2026-11-17 大屏电视构图与菜单（当前实现）

大屏沿用主窗口的“樱纸档案 / 游戏启动器”语汇：烟粉暗底、明朝体标题、樱红当前项和数据账簿。它不采用深色观影厅、放映室或海报卡片墙。当前画面把用户库中的当前作品海报贴住窗口右边，原生 2:3 画面不拉伸；同一张封面再以低亮度模糊层铺在右后方，形成环境延伸。覆盖整个视口的遮罩从右向左加深，并在底部压暗海报架所在的带状区域。

- **高清封面**：素材表新增 `assets.hero_path`。重新缓存封面时保留原图、480×720 缩略图和最高 1440×2160 的 WebP 大屏图；大屏按 `coverHeroPath → coverPath → coverThumbPath` 选择，找不到时回退到程序生成的封面。迁移为 `20261116000300_cover_hero.sql`，旧数据无需手工处理；浏览器预览仍使用生成封面。
- **背景**：右侧原生 2:3 海报贴住窗口右边，不描边、不加圆角和阴影，只保留一条向内淡出的左缘。同一张封面以高亮度模糊层铺满整屏，全屏遮罩从左侧约 58% 的梅色压暗过渡到右侧近乎透明；左侧不再是纯黑空场，仍能看到海报带出的色块、柔光和颗粒。遮罩叠加封面主色径向光，不同作品会得到不同的环境色。
- **侧栏**：侧栏固定为 46px 图标列，分类图标无底板、圆角或卡槽；左上角应用图标与分类图标共用同一条列并水平居中。图标列在窗口边缘与分隔线之间居中，左右各保留约 12px 的呼吸位，不再贴着分隔线。焦点一进入分类项就立即切换分类，不需要按 A；当前项只提高图标亮度，并在图标左侧约 7px 处显示竖线，不再显示矩形焦点框。
- **分隔线**：只保留侧栏与主区域之间的一条竖向分隔线，`position: fixed` 顶到视口上下边缘；顶栏、主视觉账簿、书架标题和按键提示均不使用横线或边框。
- **顶部状态**：顶栏只显示当前时间，移除馆藏数量、本周时长和手柄/键盘连接文字。
- **主视觉**：左侧下方是一列连续的作品信息，贴住画面左缘，不包卡片、不做左右两栏。顺序固定为目录编号 → 标题 → 原题 → 一行横向元信息（开发商、年份、版本、容量、入库）→ 细边框标签 →“简介”横带与正文 → 四项游玩记录 → 启动按钮；标题、简介、记录和按钮共用同一条左基线。字号按视口高度取值（标题 `clamp(50px, 7.2vh, 108px)`），2560×1440 与 1920×1080 得到同一套比例，不再用宽度上限压小大屏文字。上方海报不再可聚焦，主视觉没有“游戏详情”按钮。
- **简介横带**：横带取当前海报的一条低亮度切片。宽而矮的横条本身只能露出人像封面的一小条，因此切片以 `blur(18px)` 虚化成色场，再叠加当前作品环境色与左侧压暗，最左侧留“简介”标签和樱红竖标，不包成独立卡片；没有高清图时整体退化为环境色渐变和樱红下划线，形状与有图时一致。
- **启动态**：初始焦点在底部书架；在封面按 A 或点击封面只显示启动按钮，不打开游戏菜单，Y 或右键才打开游戏菜单。显示启动按钮后书架用网格行从完整高度收至 0（`grid-template-rows: minmax(0, 1fr) → 0fr`、`opacity: 0`、`inert`、`aria-hidden="true"`），恢复时按实际内容高度平滑展开，不再依赖 `max-height` 的估算值。裁切内层使用 `overflow: clip`，不形成可滚动容器，展开期间 `scrollIntoView` 不会把书架标题移出顶部。信息块扩展到整屏：简介放宽到 5 行，介绍与记录之间、记录与按钮之间加大留白，启动按钮跟随记录左对齐并与记录保持 8–40px 间距，不再脱离记录挂到屏幕底部。文案区上下内边距、简介与记录的间距、记录与按钮的间距都带 380ms 过渡；按钮本身以 320ms 淡入上移。B/Escape 收起按钮并恢复书架。
- **启动按钮焦点**：启动按钮宽 200–250px，保持 600 字重与原字号，字距放宽到 0.06em，按钮收短后文字更显眼。聚焦时只在按钮内部显示 1px 暖白细线，不添加外层厚环或第二层底板；表面以约 3.8 秒一轮的带停顿斜向扫光持续循环，文字与背景亮度保持稳定。按钮图标向确认方向轻移 2px，减少动效时停在静态细线。
- **按键提示**：底部按键提示由“设置 → 电视大屏 → 按键提示”控制，持久化字段为 `useAppearance.bigScreenHints`，也可在 Start 控制菜单里直接隐藏或显示；关闭后内容区按自身节奏收底，不保留固定空白带。
- **书架**：只显示 2:3 裸封面，无白边、底色或标题，未选中的封面保持完全不透明、不变暗。分类名与作品数并列在书架标题行，数量紧跟在标题之后，不再推到书架最右端。当前作品抬升 2–3px，并加一圈 2px 樱红外框、1px 暖白外沿和柔光。书架容器左缘顶到侧栏分割线，第一张海报和分类标题共用内容左基线；分割线到内容基线之间就是左侧渐隐区，渐隐结束在选中外框左缘，分割线以外直接裁切。右侧保留 36px、纵向至少 34px 的透明缓冲区，右侧 26px 渐隐。方向键保留原生平滑滚动；左侧渐隐区会吞掉正在移动的外框、封面高亮和光晕，不再需要额外的滚动隐藏层。实际焦点再增加 0.4% 放大和更亮的扩散光。`min-height: 1300px` 时封面放大到 300px 宽，避免 1440 高屏幕出现过大的顶部空区。LT/RT 或 Q/E、PageUp/PageDown 按视口整页横向滚动，平滑滚动并对齐目标封面起点；系统或应用启用减少动效时直接跳转。
- **界面动效**：切换当前作品时，新海报以短淡入替换背景，左侧档案文字轻微上移并去模糊；书架只在分类切换时让封面以最多 168ms 的错开延迟淡入，横向移动焦点只更新当前封面的外框和光晕。侧栏“全部游戏”排在第一项，樱红竖线从中心展开，作品数随分类更新时短暂上浮。所有新增状态在减少动效时保留颜色、亮度与外框，但移除位移、缩放和入场延迟。
- **横向浏览**：书架行用负左边距顶到分割线，内部再用与 `--bs-gap` 对应的左内距把海报放回内容基线，右侧保留光晕余量；卡片只用原生 `scrollIntoView({ block: "nearest", inline: "nearest" })` 跟随焦点，保持平滑滚动，不再在下一帧把焦点卡补滚到行首。根容器保持 `overflow: clip`，连续向右浏览时只有海报行移动，顶栏、侧栏和作品文案保持原位。
- **浮层**：大屏详情抽屉已删除。Y 打开锚定在当前位置的游戏菜单。Start 打开“大屏控制”，整体背景使用更强模糊，右侧列只保留五项：返回、刷新游戏库、隐藏/显示按键提示、退出大屏幕模式、关闭 Miyu；不再显示显示器、手柄状态和按键说明。控制遮罩以 240ms 从透明、无模糊过渡到烟粉模糊层，右侧列以 280ms 从右边轻移进入；关闭时遮罩在 200ms 内恢复清晰并淡出，菜单在 220ms 内向右侧退场，240ms 后卸载并把焦点还给原来的位置。关闭 Miyu 先进入同一列的确认态（取消 / 关闭 Miyu），确认后调用 `app_quit` 退出进程。减少动效时直接关闭，不保留等待窗口。
- **大屏搜索**：海报列表未收起时按 SELECT（手柄按钮 8）或 F、/ 打开右侧搜索键盘。搜索词是不可聚焦的显示层，打开时焦点在数字键 1；键盘按 10 列排布为数字行、QWERTY、ASDFGHJKL+退格，底行 ZXCVBNM+宽空格，清空与关闭收在键盘下方操作栏。X 退格、Y 空格、RB 清空、B 返回分别标在对应按键或操作按钮上；输入框显示闪烁插入点与 0/48 字符计数。键帽为宽键，焦点用玫瑰色填充、细亮边和柔光，不使用外圈粗描边。关闭时遮罩淡出、面板向右轻移淡出，240ms 后卸载并恢复焦点。搜索基于当前分类，结果直接替换海报列表，分类标题变为“关键词”的搜索结果；浮层降低模糊度，左侧仍能看到结果。按 B 收起键盘后搜索词和当前分类保持不变：有结果时焦点回到结果海报，无结果时保留空状态、查询词和“查看全部游戏”，不会因焦点恢复重新选择分类或清空搜索。再按 SELECT 可以继续编辑。按键提示同步增加 SELECT 搜索。
- **输入**：A 确认、B 返回、Y 游戏菜单、Start 控制菜单；LB/RB 只切换左侧分类，不切换焦点区域或打开菜单，切换后保留当前工作区焦点；LT/RT 翻页。方向键在书架上只做横向移动，不再把焦点送去分类栏；键盘用 Tab 进入分类栏。启动按钮显示期间方向键被锁在按钮上，LT/RT 也不翻页，只有 LB/RB 切换分类、B/Escape 收起。X 未分配；键盘方向键、Enter、Escape、C、M、Tab、Q/E 和 PageUp/PageDown 提供完整替代。B/Escape 只逐层返回，根界面不退出大屏。

## 2026-11-16 Atelier 产品界面层（基础层）

这一轮保留“樱纸档案 / 游戏启动器”的视觉方向，把原先分散在各个页面 CSS 里的字号、控件、面板、菜单和动效收成一套产品界面层。共享规则按加载顺序位于 `src/design-system/tokens.css`、`components.css` 和 `atelier.css`；页面只保留自己的版式职责。

- **字体角色**：界面主字体改为自托管的 Noto Sans SC Variable，中文、英文控件和正文使用同一套无衬线字形；页面标题和游戏名使用 Noto Serif SC Variable；时长、计数、编号、路径和统计数字使用 Manrope Variable / Cascadia Mono。日文原题继续使用 Noto Serif SC / Yu Mincho。
- **字号层级**：功能文字最小 12px，常规辅助文字 13px，控件与密集信息 13.5–14px，正文 15px，卡片标题 18px，区块标题 22px，页面标题 42px，详情游戏名 54px。封面内部随容器缩放的排印不属于界面字号；除此之外不再使用 9.5–11.5px 的功能性小字。

- **数据条**：最近游玩与本地安装从窄侧栏移到主视觉下方两张横向卡片。最近游玩显示 3 条会话；本地安装显示可执行文件、工作目录、安装状态、平台、版本和大小，并提供路径校验。
- **校验状态**：点击“校验路径”后，按钮变成路径状态，可执行文件和工作目录图标同步显示结果；两条详细消息放在卡片内的浮层中，不改变卡片高度。结果浮层支持关闭和重新校验。
- **页签与内容**：页签使用图标、完整/短标签和 spring 移动的粉色胶囊；支持左右方向键、Home、End。切换页签时用滚动锚定保持标签在视口中的位置，短内容也不会被浏览器夹回顶部。
- **动效**：详情主视觉进入一次淡入，封面框延迟轻放到位；封面悬停放大 1.015；最近游玩条形图绘制一次；页签胶囊与内容切换使用短时过渡。应用内“减少动效”和系统 `prefers-reduced-motion` 都会移除位移、缩放和描边绘制。
- **通知**：Toast 固定在右下角，并限制最大宽度，不再压住左侧导航。
- **范围**：本轮以首页和全局外壳为基准；游戏库、详情、统计、设置、收藏集已继承新 token 与外壳，后续逐页按同一套间距、字号和状态规范继续收口。

## 产品定位（本轮校正）

MiyuManager 是 Windows 上的本地 **Galgame / AVG 电子游戏库管理器**。它管理的是可以启动的游戏、游戏发行版本、本地安装副本、可执行文件、工作目录、启动配置、元数据来源、游玩会话与用户状态。

它不是电子书管理器、视频库、游戏商店，也不是游戏内进度追踪器。

v1 的界面只展示管理器能够可靠获得的数据：

- 本地安装路径、可执行文件、工作目录和启动参数。
- 启动次数、最近启动时间、累计游玩时长和会话记录。
- 用户自己设置的游玩状态、评分、收藏和备注。
- 从 VNDB、Bangumi、Steam 等来源获取并保留来源字段的元数据。

界面不显示“攻略进度 42%”“第 6 章”“透子线”这类游戏内状态。管理器不注入游戏、不读取游戏内存，也不承诺读取存档或路线进度。用户状态和备注可以手写，但不能伪装成自动读取的数据。

## 设计主张

**先把“游戏库”做得像游戏，再把它做得像一个可靠的本地工具。**

封面、包装、启动、游玩时长和库里有什么，是第一眼要回答的问题。界面可以借用游戏主机、收藏架和游戏频道的视觉语言，但落点始终是本地游戏管理，不是商店橱窗、影视资料馆或阅读器。

## 三个方向

G1 已选择 **A 游戏启动器**。B 和 C 保留为对照记录，不再作为主方向。

### A. 游戏启动器 / Midnight game box

视觉母题最初是“深夜游戏盒”：深墨蓝的实体包装盒、奶油色盒面、樱桃红标签和薄荷色状态。C8 曾把 token 迭代为“樱纸档案”：雾粉纸面、深墨侧栏、樱红强调、灰绿状态和黄铜数据。2026-11-15 首页重构进一步把侧栏与窗口栏改为樱粉、顶栏改为浅粉，保留游戏包装、封面舞台与真实数据作为主视觉，不再使用深墨侧栏压场。

- 首页：当前游戏、上次游玩、累计时长、启动次数、安装大小，最近启动和最近入库。
- 游戏库：六列封面架，状态、引擎、年龄分级、累计时长和上次游玩。
- 详情：封面、游戏资料、启动面板、游玩会话、本地安装和元数据来源。

优势：游戏感最强，适合每天打开；结构可以直接延伸到手柄和大屏。  
风险：深色主题需要控制长时间阅读的对比度；红色只承担“启动/标签”，不能泛滥成警告色。

### B. 游戏收藏架 / Personal game shelf

暖纸色背景，实体游戏包装盒、彩色书脊、收藏标签和编号。标题使用粗黑体，日文原题使用明朝体；信息密度高，像整理自己的游戏架，而不是商店货架。

- 首页：最近入库的游戏包装、个人评分、游玩状态、最近游玩记录；右侧是库中数量和本周游玩时长。
- 游戏库：左侧状态/年份筛选，右侧四列实体包装卡；每张卡显示书脊、编号、引擎、年龄分级和上次游玩。
- 详情：把作品做成一张可阅读的游戏资料页，包含包装、发行信息、启动配置、游玩记录和来源记录。

优势：最适合大量本地作品、元数据整理和“我记得我买过这个”的发现场景。  
风险：必须持续使用“个人收藏 / 最近添加 / 游玩记录”，避免滑回商店的“新入荷 / 店长推荐 / 营业中”。

### C. 游玩频道 / Personal play log

播控蓝背景，节目黄、直播橙和信号青。把最近游玩和游玩时长组织成节目单和 OSD，而不是发售日历。

- 首页：最近启动的游戏作为“LAST PLAYED”主画面，右侧是最近游玩会话列表；下方是最近启动和想玩清单。
- 游戏库：三列 16:9 节目卡，封面海报、标题 OSD、状态、引擎、累计时长和上次游玩。
- 详情：节目档案式大画面，叠加游戏资料、游玩数据、启动配置和最近游玩。

优势：最适合大屏模式和“最近玩了什么”的回顾；视觉节奏最强。  
风险：电视语汇要服务于游戏管理，不能变成发售新闻、商店推荐或影视流媒体。

## 动效

- 主视觉在页面切换时使用一次轻微淡入和 4–8px 位移，不做逐卡入场。
- 封面悬停 180–220ms，位移不超过 4px；按钮反馈 100–160ms。
- 减少动效时保留状态变化，移除位移和缩放。
- 大屏模式在 C7 再设计焦点环和遥控反馈。

## 反模式

- 不显示游戏内进度、章节、路线、存档状态，除非未来用户明确手动填写并标注为“用户备注”。
- 不使用“阅读、已读、在读、馆藏、放映、书库”等电子书或影院语汇。
- 不使用“新入荷、店长推荐、营业中、发售表、商店”等商店语汇。
- 不把统计数据做成假进度条；进度条只用于真实可解释的会话时长或安装进度。
- 不用统一的 SaaS 圆角卡片堆满整页，不用整窗模糊和无意义霓虹。
- 不把“Galgame”做成只有粉色和女角色的刻板视觉；游戏封面、包装和信息结构才是主体。

## 当前实现与证据

### 2026-11-15 可读性与圆角修订（历史记录）

这一轮针对“字体过小过淡”和“组件太方正”做了统一调整，数值集中在 `src/design-system/tokens.css`，后续主题或布局重做时可以直接覆盖。

- 弱文本对比度提高：`--color-text-muted` 0.90、`--color-text-soft` 0.78、`--color-text-faint` 0.64；不再用 0.56 的奶油色承载元数据。
- 字号层级提高：caption 11px、meta 11.5px、UI 13px、body 14px、title 16px；主界面功能文字以 11px 为下限，封面内部的装饰性排版不计入该下限。
- 圆角分层放大：控件 10px、卡片 16px、面板 18px、主视觉 24px、封面 8px、弹层 18px；标签保持胶囊形，避免整页由同一种圆角构成。
- 控件尺寸随字号一起增加：默认按钮高 38px，小型按钮高 32px；顶栏搜索、视图切换和图标按钮同步放大。

### 2026-11-15 C4 元数据来源

详情页“来源与字段”现在是一张可操作的工作台：顶部搜索框默认带当前原题或标题，来源筛选显示“全部来源 · 按优先级”；左侧候选按来源优先级排列，保留封面、标题、年份、开发商、来源徽标和评分；右侧导入预览用“当前值 → 候选值”展示差异，封面单独确认。

搜索结果和多源工作台沿用樱纸界面：来源徽标使用数据色，可用状态使用薄荷，空值和日期使用等宽字体；候选字段以方形分格呈现。设置页的来源优先级使用编号、上下移动和启停，不引入拖拽依赖。

字段导入默认只勾选空白字段；已有手动/本地封面默认保留。用户可以逐项勾选要写入的字段。字段锁定机制已移除，旧锁定值在迁移中清零。

设置页“账号与同步”使用三排横向账号卡：每排先显示平台图标，再显示头像、用户名、账号 ID、平台能力、资料同步和令牌状态；连接按钮会打开系统浏览器，等待授权期间显示“等待授权”，成功后卡片显示真实头像和用户名。“同步资料”会重新读取平台资料并写回 SQLite；OAuth 的错误提示直接说明下一步，例如 Hikarinagi 需要把应用改为 public client。

### 2026-11-15 C5 多源合并与批量刮削

详情页新增“一次比较所有来源”的合并工作台：顶部显示每个匹配来源的标题和置信度，下面按字段列出“当前值 → 各来源候选”。候选以来源徽标 + 值的方形分格排列，点击即切换选择；冲突字段使用标签红“冲突”。底部图片候选按“封面 / 胶囊 / 横幅”分组，以各自比例展示，用户选图而不是读 URL；已有封面默认不选。

字段优先级设置增加一个总开关：“全部字段跟随全局来源顺序”。关闭时每个字段独立排序，展开后可上下移动来源并恢复默认；打开后所有字段立即使用上方来源顺序，字段级控件变灰但覆盖值保留。全局状态用“全局顺序 / 字段级”标签和“全局”行标记表达，不把两种模式混在同一个列表里。

游戏库进入批量模式后，封面卡显示圆形选择标记，底部出现批量操作条：已选数量、退出多选、全选、清空和“开始批量刮削”。多次框选会保留已有选择，只增不减；批量弹窗先选择来源和是否补封面，再显示进度、暂停/取消；完成匹配后进入提案审阅，每部作品可展开字段差异，失败项单独标记并可重试。应用完成后显示局部成功摘要，不把整批任务做成一个不可中断的黑盒。

Steam 库扫描沿用同一套“先确认再入库”的模式：游戏库头部提供“扫描 Steam 库”，弹窗自动从注册表和 `libraryfolders.vdf` 读取库路径，再显示每部 Steam 游戏的 AppID、安装目录、大小、更新时间和主程序候选。扫描中显示当前游戏、进度和取消入口；扫描完成后默认勾选找到 exe 且未入库的作品，可以逐项修改显示名称、切换主程序，已入库作品明确标记并禁用。封面卡在游戏库中保持原有视觉，不增加 Steam 专用装饰。

### 2026-11-15 C6 游玩会话与统计

统计页现在使用真实 `play_sessions`：顶部显示累计、最近 7 天和本周启动，时间范围按钮控制作品排行和最近会话；18 周热力图按本地日期显示每日时长，跨午夜会话归入开始日期并在界面中明确说明。热力图使用固定正方形的七日列布局，不因宽屏把单元格拉成高低不一的色块。

作品详情的“游玩记录”沿用原有表格，但增加结束状态、备注和行内操作。补录/修正使用同一张内嵌表单，开始与结束时间使用浏览器本地时间输入；自动会话用“计时中 / 后台暂停 / 正常退出 / 手动停止 / 异常恢复”表达状态，手动记录带“手动”标签，修正过的记录带“已修正”标签。短会话按秒显示，避免不足一分钟时误显示“尚未记录”。

Steam 导入的作品在封面左下显示薄荷色 `Steam` 标记，详情标签显示 `Steam 库 · AppID`，列表来源列显示 `Steam · 本地安装`。这些标记直接来自 `steam_app_id`，不根据目录名字猜测。Steam 可能先启动短转交进程再以新 PID 启动真正游戏，因此会话页显示的游戏进程来自最终附着的完整 exe，而不是最初的启动 PID。

Home、Library、Stats、Detail 和 Settings 不再使用固定页面宽度；内容跟随左侧导航之外的可用区域伸展。窗口最大化时，首页主视觉扩展到新的可用宽度，游戏库虚拟网格重新计算列数，统计与会话表格获得更多横向空间。1440、1920、150% 缩放、4K 和当前屏幕的 2048×1104 最大化视口均保持无横向溢出。

### 2026-11-15 C7 电视大屏（历史记录，当前实现以上方“大屏整屏海报”为准）

大屏是一个独立的无边框全屏窗口，由设置页选择显示器后打开。页面用当前作品的封面做全屏模糊环境底，叠加深色渐变；主视觉不再包在卡片里，左侧是状态、标题、原题、简介、标签和操作，右侧是 2:3 竖版封面，底部是横向海报架。书架中的海报同样使用 2:3 比例，只显示画面，不显示标题、开发商或入库时间；分类名和数量只出现在书架标题行。“最近入库”不进入大屏。

分类切换放在左侧的纯图标栏，垂直居中，只有图标和选中标记，没有文字、计数或分组标题；分类名通过 `aria-label` 和悬浮提示提供。焦点按分类栏、主视觉、书架分区管理：从分类栏向右进入主视觉，从主视觉向下进入书架；LB/RB 和 Tab 在三个区域之间循环，并记住上一次停留的焦点。

Y 在当前位置打开游戏菜单，而不是随机启动：菜单包含启动/停止、查看详情、收藏、游玩状态子菜单和关闭。Start 从右侧打开控制侧栏，包含显示器、手柄状态、按键说明、刷新游戏库和返回主窗口。X 未分配；B/Escape 只逐层返回，根界面不会退出大屏，退出入口集中在控制侧栏。设置页保留显示器选择、手柄连接状态、打开按钮和简短键位提示。

焦点环保持 3px 樱红外描边加 2px 深色内描边，海报在焦点时轻微抬起；鼠标静止后隐藏光标，`prefers-reduced-motion` 和页面动效开关会关闭过渡。4K 下限制封面解码尺寸，环境底只使用当前主视觉的一张图。

### 2026-11-15 C8 产品化与樱纸档案（历史基线）

C8 把整套界面从“功能页集合”收成一张摊开的樱纸档案：雾粉纸面承载内容，深墨侧栏像档案柜，樱红只用于启动和当前选中。token 在 `src/design-system/tokens.css`：`#F5EFEC` 纸面、`#FFFAF7` 表面、`#2B2225` 侧栏、`#A94E5F` 樱红、`#506B5A` 状态、`#84602D` 数据；圆角从 16–24px 收到 2–18px，阴影只保留必要的封面与弹层层级。这一记录是历史基线，当前颜色与圆角以顶部“粉白工作台”一节为准。

字体沿用已有的字体 token：标题和游戏名使用 Noto Serif SC / Yu Mincho 的明朝体气质，界面正文使用 Noto Sans SC / Microsoft YaHei UI，时长、编号和来源时间使用 Bahnschrift / Cascadia Mono。浅纸面下没有用纯白铺满整页，避免长时间阅读刺眼；侧栏保持深色，继续承担“游戏盒/档案柜”的边界。

首页把真实数据分成主视觉、数据带、最近启动、最近入库、收藏和想玩清单。主视觉优先显示最近启动的作品，没有会话时回退到最近入库；没有作品时直接给出添加目录入口。所有模块共享同一张封面卡、状态标签和空状态，不再用假进度或商店语汇填充版面。

收藏集列表以带编号的档案卡展示名称、数量和封面栈，并在末尾提供新的收藏集入口；详情页从游戏库搜索并批量加入作品。全局搜索用 Ctrl+K 打开，以作品和收藏集分组，支持方向键、Enter、Escape 与最近搜索；关闭后焦点回到顶栏搜索。设置页使用固定目录和滚动高亮，启动器默认值、网络代理、数据目录和更新检查都显示真实状态；首次启动按“目录 → 扫描 → 确认主程序 → 可选来源 → 完成”组织成单一流程。

视觉证据：`outputs/app/c8/` 保存 C8 功能和尺寸证据，`outputs/app/redesign/` 保存上一轮全路由视觉截图，`outputs/redesign-v2/` 保存本轮首页与响应式截图，`outputs/app/c8/probes/` 保存键盘与 reduced-motion 证据。
