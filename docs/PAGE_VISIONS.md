# A 方案页面设想

> 方向：A 游戏启动器 / Midnight Game Box  
> 状态：主应用已按本文件实现；G2 已确认，C3 详情编辑、封面和启动配置已落地，C4/C5 多源元数据、Steam、合并、冲突、封面画廊和批量刮削已落地，C6 自动游玩会话与统计页已落地，C7 大屏已实现，C8 已补齐首页、收藏集、全局搜索、设置和首次启动。2026-11-16 已按“Atelier 产品界面层”统一字体、页头、控件、弹窗、首次启动与大屏；当前视觉权威记录见 `docs/DESIGN.md` 的同日章节
>
> 数据边界：只展示本地安装、启动、会话时长、用户状态/评分/评价和可追溯元数据；不显示游戏内章节、路线、存档或进度百分比。

## 设计基调

主界面像一张摊开的樱纸档案：雾粉纸面、深墨侧栏、樱红标签、灰绿状态和黄铜数据；结构仍来自实体 Galgame 包装盒。它不是霓虹主机界面，也不是影视放映厅。樱红只用于“启动、选中、标签”，灰绿用于“可玩、可用、在玩”，黄铜色用于“时长、次数、编号”等需要被读数的信息。

标题使用粗黑体，中文和拉丁都收紧字距；日文原题保留明朝体，作为包装上的第二层文字，而不是每张卡片都重复的装饰。列表数据使用等宽字体，但只出现在时长、启动次数、编号和来源时间上。

## 1. 首页 / Home

**页面任务**：打开应用后，三秒内回到最近在玩的游戏，同时知道库里最近发生了什么。

布局：

- 左侧固定导航：首页、游戏库、收藏集、统计、设置；底部显示库中数量和扫描目录。
- 顶部栏：面包屑、全局搜索入口、添加目录和离线状态；Ctrl+K 打开作品/收藏集搜索。
- 主视觉：左侧是“上次游玩”的游戏标题、原题、简介、类型、引擎/年龄分级；右侧是实体包装比例的封面。主按钮是“启动游戏”，次按钮是“游戏详情”。
- 主视觉下方是一条真实数据带：累计时长、启动次数、安装大小、上次游玩。没有进度条。
- “最近启动”横向四张卡片：封面、状态、标题、原题、累计时长、上次游玩。
- “最近入库”六个小封面：标题、开发商、入库时间；用于快速发现新加入的游戏。

交互与状态：

- 点击主视觉封面或标题进入详情；点击“启动游戏”调用启动器，失败时在按钮下方给出可操作提示。
- 没有最近启动时，主视觉切换为“最近入库”的游戏；完全没有游戏时显示添加目录的引导。
- 加载时保留主视觉骨架和卡片尺寸，避免布局跳动；错误状态提供重试。
- 键盘：Tab 进入导航与主视觉，Enter 进入详情，Ctrl+K 打开搜索。

不做什么：不显示“攻略进度 42%”，不显示“第 6 章”，不把“继续游玩”写成能从游戏内断点恢复。

## 2. 游戏库 / Game Library

**页面任务**：在几百到几千部游戏中快速找到、筛选和批量管理作品。

布局：

- 顶部工具栏固定：标题、总数、在玩/想玩/已通关/搁置筛选、搜索、添加游戏、排序、封面/列表切换。
- 默认六列封面墙；窄窗口降到五列或四列。每张卡只显示封面、状态、标题、原题、引擎/年龄分级、累计时长和上次游玩。
- Steam 库导入的作品在封面左下显示 `Steam` 标记；列表视图的来源列显示 `Steam · 本地安装`，避免把商店来源和本地副本混淆。
- 详细筛选放在右侧抽屉：来源、年份、引擎、安装大小、本地状态；不默认占据一列，避免和左侧主导航争夺空间。
- 多选模式：选择后底部出现批量操作条；当前已接入“批量刮削”，保留标记状态、收藏集、重新扫描和移除本地副本的入口。批量操作必须有明确数量和撤销入口。
- Steam 库：工具栏提供“扫描 Steam 库”，自动定位 Steam 根目录和所有库文件夹，列出 appmanifest 中的游戏、AppID、大小和 exe 候选；确认后入库并保留 Steam AppID。

交互与状态：

- 方向键在网格中移动，Enter 打开详情，Space 选中；Shift+方向键连续选择。
- 搜索输入 150–200ms 防抖；筛选结果数量即时更新；空结果说明当前筛选条件并提供清除。
- 大库使用 TanStack Virtual 行虚拟化；封面只加载缩略图；首屏骨架保持卡片尺寸。
- 排序默认“按最近启动”，可切换“最近入库 / 标题 / 累计时长 / 评分”。

不做什么：不在卡片上放虚假进度条；不把“已通关”当成自动检测结果，它来自用户状态。

## 3. 作品详情 / Work Detail

**页面任务**：确认这是哪部作品、它装在哪里、怎么启动，并管理这次游玩留下的数据。

布局：

- 顶部返回游戏库；主区左侧是大幅实体包装封面和版本/年龄分级；右侧是标题、原题、类型、个人评分、用户状态。
- 右侧数据带：累计时长、上次游玩、启动次数、安装大小。主按钮“启动游戏”，次按钮“编辑资料”和“启动配置”。
- 下方使用四个分区或标签：
  1. **游玩记录**：显示真实会话的起止时间、有效时长、结束方式和备注；可编辑、删除、补录。自动会话会区分计时中、后台暂停、正常退出、手动停止和异常恢复。
  2. **启动配置**：游戏目录与可执行文件名组成一组路径字段；启动参数和兼容包装器各占一整行卡片。兼容包装器列出 Locale Emulator 与 Magpie，各自只显示启用开关；程序路径和参数在设置页分别维护。Magpie 开启后会在窗口出现时自动写入本作品规则并以托盘模式缩放；显示器与全屏沿用已保存配置，不在详情页重复出现。
  3. **元数据来源**：C4/C5 已接入 VNDB、Bangumi、NextMoe/Kungal、Hikarinagi、Steam 的搜索、候选预览、字段来源、更新时间、冲突处理、封面画廊和批量重新抓取。导入候选默认只勾选空白字段，用户可以明确勾选要覆盖的字段；封面按缩略图比较，URL 只留在来源记录中。字段锁定机制已移除。
  4. **本地安装**：安装目录、版本、占用空间、重新扫描、在资源管理器中打开；Steam 来源同时显示 `Steam 库 · AppID`。
- 从 Steam 库扫描入库的作品在“游戏资料”中显示 Steam AppID；后续“来源与字段”的 Steam 匹配直接使用该 AppID。
- 左侧保留“用户评价”，当前来源标记为“本地”；后续可接入 Bangumi、Kungal 等社区评论，但外部来源与本地评价必须分开标注。
- 概览采用单列作品档案：简介、别名、标签、游戏资料、来源和库编号在同一张“关于这部作品”卡片内；简介不使用多栏排版。
- 主启动操作右侧在存在来源 ID 时提供带文字的 Bangumi 与 Kungal 入口，使用两站自己的图标并打开对应作品页；来源 ID 在多源匹配或搜索导入时同步保存。

交互与状态：

- 保存或启动前校验 exe、工作目录和已启用的包装器；错误提示包含“哪个路径、为什么失败、怎么修复”，不暴露敏感堆栈。
- 启动配置改动即时生效：文本输入防抖保存，目录选择、可执行文件选择和包装器开关立即保存；不再显示手动保存、保存并启动按钮或常驻自动保存提示。
- 元数据字段的编辑先进入草稿态，保存后才写入；重新抓取前在候选预览中逐项确认字段。
- 无封面使用标题排印 fallback；断网时本地数据、启动和会话仍然可用。

不做什么：不显示从游戏内读取的路线、章节、CG 收集率或存档状态。

## 4. 大屏模式 / Big Screen

**页面任务**：在电视和手柄上，以大焦点和少文字完成“找到游戏并启动”。

布局：

- 独立 Tauri 窗口，全屏、无边框；顶部只保留当前时间，按键提示由“设置 → 电视大屏 → 按键提示”控制，默认显示在底部。
- 整屏背景由右侧原生 2:3 的当前作品海报和全屏烟粉遮罩组成；海报上下贴满视口并贴住窗口右边、不加边框或阴影，同一张封面以模糊层铺满整屏，遮罩从右向左逐渐加深但左侧仍保留可见的环境色、柔光和颗粒。顶栏、分类栏、文案与书架共享这一张背景。左上角只保留侧栏里的应用图标，没有独立顶栏品牌。
- 左侧是 46px 纯图标分类栏，无背景色或卡槽；左上角应用图标与分类图标共用同一条列并水平居中。图标列在窗口边缘与分隔线之间居中，左右各保留约 12px 的呼吸位，不贴向分隔线。焦点进入分类项时立即切换分类，当前项只提亮图标并在图标左侧显示竖线，不显示矩形焦点框。不显示分类文字、计数或分组标题。除分类栏与主区域之间的竖向分隔线外，不使用其他分节横线；分隔线使用 `position: fixed` 顶到视口上下边缘。
- 海报列表未收起时按 SELECT（手柄按钮 8）或 F、/ 打开右侧搜索键盘。搜索词是不可聚焦的显示层，打开时焦点在数字键 1；键盘按 10 列排布为数字行、QWERTY、ASDFGHJKL+退格，底行 ZXCVBNM+宽空格，清空与关闭收在键盘下方操作栏。X 退格、Y 空格、RB 清空、B 返回分别标在对应按键或操作按钮上；输入框显示闪烁插入点与 0/48 字符计数。键帽为宽键，焦点用玫瑰色填充、细亮边和柔光，不使用外圈粗描边。关闭时遮罩淡出、面板向右轻移淡出，240ms 后卸载并恢复焦点。搜索基于当前分类，结果直接替换海报列表，分类标题变为“关键词”的搜索结果；浮层降低模糊度，左侧仍能看到结果。按 B 收起键盘后搜索词和当前分类保持不变：有结果时焦点回到结果海报，无结果时保留空状态、查询词和“查看全部游戏”，不会因焦点恢复重新选择分类或清空搜索。再按 SELECT 可以继续编辑。底部按键提示包含 SELECT 搜索。
- 主视觉不再使用卡片、白底或海报边框：左侧下方是一列连续的作品信息，贴住画面左缘，不包卡片、不做左右两栏。顺序固定为目录编号、标题、原题、一行横向元信息（开发商、年份、版本、容量、入库）、细边框标签、“简介”横带与正文、四项游玩记录、启动按钮；标题、简介、记录和按钮共用同一条左基线，字号按视口高度取值。简介默认 3 行、启动态 5 行；“简介”横带取当前海报的低亮度切片并做模糊处理，横条里只露出封面的一小条也不显得断裂，不是独立卡片；没有高清图时用作品环境色渐变保持同一形状。右侧露出原生比例海报。主视觉没有“游戏详情”按钮，进入详情只能从游戏菜单。
- 初始焦点在底部书架，方向键只在书架内横向移动，按 Tab 才进入左侧分类栏；上方海报不可聚焦。在封面按 A 或点击封面只显示启动按钮，不打开游戏菜单；Y 或右键才打开游戏菜单。启动后书架用网格行按实际内容高度收至 0，透明、`inert`、`aria-hidden`；恢复时完整高度平滑展开。裁切内层使用 `overflow: clip` 而不是可滚动容器，展开时标题不会被 `scrollIntoView` 推走或裁切。启动态里方向键与 LT/RT 都被锁在按钮上，只有 LB/RB 切换分类、B/Escape 收起；启动按钮跟随记录左对齐并保持 8–40px 间距，宽 200–250px、600 字重、字距 0.06em，不脱离记录挂到屏幕底部。文案区的内边距与间距带过渡，收起和恢复都是平滑移动。
- 底部是横向海报架，只显示 2:3 裸封面，不在海报下方放标题或开发商；分类名与作品数并列在书架标题行，数量紧跟在标题之后。未选中的封面保持完全不透明、不变暗；当前作品轻微抬升并带柔光，外侧有 2px 樱红外框和 1px 暖白外沿，远距离也能明确识别。书架容器左缘顶到侧栏分割线，第一张海报与分类标题共用内容左基线；分割线到内容基线之间整段作为左侧渐隐区，渐隐结束在选中外框左缘，分割线外直接裁切。右侧保留透明缓冲区和渐隐。方向键保留原生平滑滚动，左侧渐隐区会吞掉移动中的外框和光晕，不需要额外的滚动隐藏层。LT/RT 或 Q/E 按视口整页横向滚动，带平滑过渡并对齐目标封面起点；减少动效时直接跳转。大屏不显示“最近入库”。
- Y 在当前位置打开游戏菜单；Start 打开“大屏控制”，以模糊遮罩覆盖整页，右侧列只有返回、刷新游戏库、隐藏/显示按键提示、退出大屏幕模式、关闭 Miyu 五项，关闭 Miyu 需要二次确认。控制遮罩和右侧列有明确的进入与反向退出过渡，关闭动画结束后才释放焦点；减少动效时立即关闭。不再显示显示器、手柄状态和按键说明，也不再提供大屏详情抽屉。
- 选中海报使用轻抬、柔光和双层外框区分；实际焦点使用更亮的柔光扩散和约 0.4% 放大，保证 3 米外可见。启动按钮的焦点是按钮内部 1px 暖白细线，表面以约 3.8 秒一轮的带停顿斜向扫光持续循环，不使用外层厚环。侧栏“全部游戏”排在第一项，当前项竖线从中心展开，并随图标亮度一起变化。鼠标悬停只提供轻微封面抬升，不作为唯一操作路径。

交互：

- D-pad / 左摇杆移动，A 确认，B 返回，Y 游戏菜单，Start 控制菜单，LB/RB 只切换左侧分类，LT/RT 翻页；X 未分配。LB/RB 不移动焦点区域，切换后保留当前工作区焦点。启动按钮显示期间方向键被锁在按钮上，只有 LB/RB 能离开。
- 游戏菜单包含启动/停止、查看详情、收藏、游玩状态子菜单和关闭；控制菜单只有返回、刷新游戏库、隐藏/显示按键提示、退出大屏幕模式和关闭 Miyu，关闭 Miyu 需要二次确认。
- B/Escape 只逐层返回，根界面不退出大屏；退出大屏和退出应用都只在控制菜单。
- 焦点丢失时回到上次卡片；关闭菜单后焦点回到触发卡片。
- 手柄不可用时，键盘方向键、Enter、Escape、C、M、Tab、Q/E 和 PageUp/PageDown 提供完整替代；启动失败留在当前页并提示。
- 连续向右选择海报时，海报行有明确的可滚动宽度，只用原生 `scrollIntoView({ block: "nearest", inline: "nearest" })` 跟随焦点，不再把焦点卡强制补滚到行首；页面、根布局、顶栏和侧栏不会横向移动或偏移。

性能：

- 背景使用当前作品的高清封面缓存：右侧原生 2:3 海报加同图模糊环境层；重新缓存时生成最高 1440×2160 的 WebP，避免 4K 下把 480×720 缩略图放大。浏览器预览回退到生成封面。
- 只对焦点移动、菜单、分类切换和书架翻页使用过渡；横向移动焦点不重放书架入场。分类切换时封面最多延迟 168ms 收拢，减少动效时直接呈现。

## 5. 统计 / Stats

**页面任务**：回答“我最近玩了多久、都在玩什么”，而不是展示游戏内完成度。

布局：

- 顶部显示累计时长、最近 7 天和本周启动；时间范围按钮控制作品排行与最近会话。
- 中间是 12 周每日热力图；下面按游戏列出范围内累计时长和最近会话。
- 右侧是最近会话列表，可编辑/删除/补录。
- 时间范围筛选：本周、本月、今年、全部；按 local copy 或作品分组。

不做什么：不做路线完成率、CG 收集率、成就进度。

## 6. 设置 / Settings

**页面任务**：管理库、来源、启动默认值和数据安全，让用户知道每个设置影响什么。

分区：

- **游戏库**：扫描根目录、忽略规则、重新扫描。
- **元数据来源**：全部 Provider 的来源顺序、启停和请求限速；C4/C5 已提供编号、上下移动、字段级排序和“全部字段跟随全局来源顺序”开关。账号连接单独成卡，显示 Bangumi、Kungal/NextMoe、Hikarinagi 的头像、用户名、scope 能力和资料同步入口。
- **启动器**：默认显示器、全屏，以及 Locale Emulator 与 Magpie 的独立路径、参数。
- **外观**：主题、减少动效、界面密度；不提供主题市场。
- **数据**：数据目录、备份/恢复、数据库迁移状态。备份使用 SQLite 在线快照；恢复前自动保留当前数据库，并在重启后完成替换。
- **关于与更新**：版本、自动更新、诊断日志、隐私说明。启动后每 24 小时检查 GitHub Release；设置页确认下载和安装，更新包必须通过 Tauri 更新签名；日志只写本地，不上传。

交互：表单校验、未保存提示、破坏性操作二次确认；设置写入 Rust 侧，不在前端直接改文件。

## 7. 首次启动 / Onboarding

**页面任务**：让新用户完成“添加目录 → 扫描 → 确认主程序 → 进入游戏库”。

步骤：

1. 欢迎：一句话说明本地优先、数据留在本机。
2. 选择目录：添加一个或多个扫描根目录。
3. 扫描：显示进度、已发现候选、取消和错误重试。
4. 确认：一个目录可能只有一个主程序，也可能有多个版本；用户确认 exe、显示名和工作目录。
5. 来源：可跳过 VNDB/Bangumi/Steam 配置。
6. 完成：进入首页或游戏库。

视觉：居中一张大纸面式面板，步骤指示只用于真实顺序；不做连续卡片堆叠。扫描失败时保留已选目录，允许重试。

## 8. 收藏集 / Collections

**页面任务**：把作品按自己的理由手动分组，不改变作品状态、安装和游玩记录。

布局：

- 列表按行显示收藏集名称、作品数量、更新时间和封面栈；有封面时显示 1–3 张缩略图，没有封面时显示分组图标。
- 支持新建、重命名、删除和上下移动；删除只移除分组，不删除作品。
- 详情页从游戏库搜索并批量添加作品，卡片可单独移出收藏集；作品本身仍从游戏库打开。

交互与状态：

- 收藏集名称不区分大小写唯一，最多 80 个字符；空状态直接给出新建入口。
- 添加作品弹窗支持搜索、多选和加载更多，已经在本收藏集中的作品不会重复出现。
- 本轮不做规则引擎、自动同步或云端收藏集；全局搜索可以按收藏集名称跳转。

## 全局状态与边界

- 所有页面共享同一套 token、按钮、Cover、Surface、Tag、Toolbar、EmptyState、Toast 和 FocusRing。
- 页面宽度跟随主内容区，不使用固定 1400/1500px 上限；窗口最大化或还原后，封面列数、统计面板和详情栏位同步重排。
- 所有“图标 + 文字”操作都有可读文本，不只靠图标传达。
- 空状态是行动入口，不是空白页；错误状态说明原因和下一步。
- 不使用 hover 作为唯一交互；键盘和大屏优先。
- 项目尚不读取游戏内进度；如果未来加入“路线评价”，必须显示为本地手写内容，并与社区来源分开。
